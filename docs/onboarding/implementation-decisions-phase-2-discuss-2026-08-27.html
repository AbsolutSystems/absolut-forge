Decyzje implementacyjne: discuss + consult

Checkpoint dla człowieka po finalnym review implementacji. To nie jest dodatkowy gate jakości kodu — pokazuje wybory, fakty i odstępstwa zapisane podczas budowy.

TL;DR

Zebrano 14 remarks: 7 wyborów realizujących zaakceptowany design, 6 faktów walidacyjnych oraz 1 kontrolowany skip środowiskowy. Ogólne ryzyko jest niskie. Finalny reviewer wykrył i po poprawce zaakceptował jedną regresję schematu Briefa; wynik końcowy to 15/15 AC i 35 testów.

Akceptujesz DEC-001–DEC-014, czy prosisz o zmianę konkretnych DEC-N?

Decyzje wymagające akceptacji

DEC-001 · Jeden kontrakt konsultacji

Oryginał: Added one canonical optional-consultation contract covering Draft/Ready mutation, immutable Ready amendments, no-findings/no-artifact behavior, and routing for Building/In Review.

Weryfikacja: reguły są w references/artifact-contracts.md, a oba skille linkują właściciela.

Ocena: wybór w ramach planu; alternatywą była duplikacja reguł w skillach. Ryzyko niskie, odwracalne przez zmianę kontraktu i testów; konsekwencją jest jeden punkt prawdy.

Rekomendacja: Akceptuję.

DEC-002 · Natywne handoffy Claude i Codex

Oryginał: Added native Claude and Codex consult commands using the canonical Feature Brief path.

Weryfikacja: oba pełne polecenia istnieją w references/harness-command-contract.md.

Ocena: implementacja planu, bez nowej zależności. Ryzyko niskie; zmiana składni wymagałaby aktualizacji jednego kontraktu.

Rekomendacja: Akceptuję.

DEC-003 · ADR-003 bez tożsamości modelu

Oryginał: Recorded ADR-003 as Accepted; consultation is human-controlled, cross-harness, optional, and does not record model identity.

Weryfikacja: ADR odrzuca mandatory gate, auto-invocation, wbudowanie consult w discuss i osobny raport.

Ocena: wcześniej zaakceptowana decyzja produktowa, tutaj utrwalona. Ryzyko niskie; model identity można dodać później tylko nową decyzją.

Rekomendacja: Potwierdzam.

DEC-004 · Host-agnostic explicit-only discuss

Oryginał: Implemented one host-agnostic explicit-only discovery contract with native Claude/Codex handoff examples.

Weryfikacja: Claude ma disable-model-invocation: true, Codex allow_implicit_invocation: false; prompt opisuje jeden adaptive flow.

Ocena: kluczowy wybór implementacyjny. Alternatywa — osobne skille per harness — zwiększa drift. Ryzyko niskie, odwracalne przez metadata i kontrakt.

Rekomendacja: Akceptuję.

DEC-005 · Testy kontraktowe bez zależności

Oryginał: Contract tests use only the Python standard library and assert all traced AC tokens plus forbidden-stage absence.

Weryfikacja: focused suite i pełny discovery przechodzą bez zewnętrznego frameworka.

Ocena: wybór techniczny; alternatywa to parser YAML/test framework. Niskie ryzyko, łatwa migracja później; obecnie testy pozostają deterministyczne.

Rekomendacja: Akceptuję.

DEC-006 · Pomocnicza walidacja YAML

Oryginał: PyYAML-based quick validation was unavailable; the Codex metadata was parsed successfully with Ruby's standard YAML parser.

Weryfikacja: PyYAML faktycznie nie istnieje; finalna ochrona metadata jest zapewniona przez testy stdlib i strict Claude validation. quick_validate nie jest wymagany, bo odrzuca poprawne pole Claude.

Ocena: fakt historyczny, nie trwała architektura. Brak wpływu runtime.

Rekomendacja: Przyjmuję do wiadomości.

DEC-007 · Heading-only Feature Brief

Oryginał: Final-review fix: input validation now checks canonical required headings and ## Status in heading-only Markdown; no Brief frontmatter is required.

Weryfikacja: oba skille i dwa testy regresyjne są zgodne z dokładnym template w references/artifact-contracts.md.

Ocena: poprawka zgodności, nie zmiana designu. Ryzyko niskie; odrzucenie przywróciłoby blocker.

Rekomendacja: Akceptuję poprawkę.

DEC-008 · Explicit-only consult z approval gate

Oryginał: The consult contract is explicit-only on both harnesses, validates only Draft/Ready inputs, and keeps findings conversational until explicit acceptance.

Weryfikacja: metadata obu harnessów blokują implicit invocation; Building/In Review zatrzymują mutację.

Ocena: realizacja zaakceptowanego designu. Alternatywa — automatyczny zapis findings — narusza human control. Ryzyko niskie.

Rekomendacja: Akceptuję.

DEC-009 · Draft merge, Ready amendment

Oryginał: Draft findings merge into canonical sections; Ready findings become accepted ## Amendments, preserving the immutable baseline and producing no consultation artifact.

Weryfikacja: reguła występuje w kontrakcie, skillu, ADR i testach.

Ocena: kluczowa granica mutowalności. Alternatywy — rewrite Ready lub osobny report — zostały odrzucone. Ryzyko niskie, ale reperkusją jest konieczność jawnej akceptacji amendmentu.

Rekomendacja: Akceptuję.

DEC-010 · Pokrycie consult

Oryginał: tests.test_consult_contract covers all traced AC tokens and canonical owner links.

Weryfikacja: focused suite przechodzi, finalny gate potwierdził AC-5/6/10/11/12/13/14/15.

Ocena: potwierdzony fakt, nie nowy wybór.

Rekomendacja: Przyjmuję do wiadomości.

DEC-011 · Heading-only consult

Oryginał: Final-review fix: input validation now checks canonical required headings and ## Status in heading-only Markdown; no Brief frontmatter is required.

Weryfikacja: poprawka symetryczna z DEC-007; test regresyjny nie pozwala ponownie wymagać frontmatter Briefa.

Ocena: poprawka zgodności; ryzyko niskie.

Rekomendacja: Akceptuję poprawkę.

DEC-012 · Consult jako siódmy skill

Oryginał: Documented consult as the seventh MVP skill while keeping discuss -> build -> review -> ship as the direct core path; consultation remains optional, explicit-only, bounded, and artifact-free.

Weryfikacja: README, Product Vision, CLAUDE i skills/README są spójne.

Ocena: decyzja produktowo-dokumentacyjna zgodna z planem; alternatywa — consult jako gate — została odrzucona. Ryzyko niskie.

Rekomendacja: Akceptuję.

DEC-013 · Dokładne odkrywanie aktywnych skilli

Oryginał: Foundation tests now discover exactly skills/discuss/SKILL.md and skills/consult/SKILL.md, enforce canonical links and Claude/Codex explicit-only metadata, and reject unsupported integrations.

Weryfikacja: test fundamentu przechodzi i nie dopuszcza hooków, host-specific trees ani nowych integrations.

Ocena: bezpiecznik pilota; konsekwencją jest celowa aktualizacja testu przy dodaniu kolejnego skilla. Ryzyko niskie, w pełni odwracalne.

Rekomendacja: Akceptuję.

DEC-014 · Wynik walidacji i skip Codex

Oryginał: Integrated standard-library, JSON, strict Claude, symlink/frontmatter, and AC-token validation passed; Codex validation was skipped because PyYAML is unavailable.

Weryfikacja: po fixie 35 testów, JSON, strict Claude, symlink, frontmatter i AC-1…15 przechodzą; preflight PyYAML nadal zwraca ModuleNotFoundError.

Ocena: kontrolowany skip przewidziany w planie. Ryzyko niskie–średnie; przed aktywacją pilota warto uruchomić canonical Codex validator w środowisku z PyYAML, bez instalowania zależności w tej sesji.

Rekomendacja: Akceptuję z jawnym follow-upem walidacyjnym.

Interakcje i skumulowane konsekwencje

DEC-001, DEC-004, DEC-008 i DEC-009 tworzą jedną granicę odpowiedzialności: jeden kanoniczny Brief, jawne uruchomienie i jawna zgoda przed mutacją. DEC-002 i DEC-012 utrzymują przenośność między Claude i Codex bez rozwidlania skilli. DEC-005, DEC-010, DEC-013 i DEC-014 dają szybkie testy kontraktowe, ale nie zastępują planowanych w Fazie 7 testów behawioralnych na realnych modelach.

Informacyjne remarks i fakty

DEC-002, DEC-003, DEC-006, DEC-010 i część DEC-014 opisują stan repo lub wykonane kontrole. Nie wykryto niezaakceptowanego rozszerzenia zakresu, nowej integracji globalnej ani trwałego artefaktu konsultacji.

Brakujące lub niejednoznaczne uzasadnienie

Nie ma otwartej decyzji blokującej. Jedyny follow-up to canonical Codex validation w środowisku z PyYAML przed pierwszą aktywacją pilota. Jest to wniosek z ograniczenia środowiska, nie dowód problemu z manifestem.
