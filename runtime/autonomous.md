# Autonomous Build Runtime

Use with [common](common.md). The high-capability builder owns the whole accepted feature. [Artifact contracts](../references/artifact-contracts.md) own lifecycle and evidence schemas.

## Start and resume

Accept only the canonical Brief path. At initial Ready start, read accepted intent/amendments, artifact start/evidence sections and the [verification doctrine](../references/verification-doctrine.md). Require a non-detached feature branch, committed Ready Brief, clean worktree and empty index. The permitted consultation report is the only exception. Reject stale execution artifacts. Record HEAD as base, autonomous strategy, not-applicable methodology and chosen artifact; set Building and checkpoint before source edits, including an allowed consultation report when present.

At Building, confirm recorded branch/base, strategy and methodology. Planned state returns to build-planned with its recorded methodology; never convert it. Read accepted intent/amendments, current outcome evidence, optional map frontier and relevant source/tests. Do not preload all past outcomes or checkpoint diffs. Current Git state is implementation truth. Reconcile dirty/mid-outcome work using recorded evidence without overwriting unrelated changes or claiming a clean checkpoint. Open sibling Review blockers are required input. Consultation is optional evidence and cannot authorize changed intent.

## Coherent outcome loop

Choose an accepted outcome and inspect named symbols/paths, direct callers, targeted tests and local dependencies before broader searches. Use an optional execution map for dependent outcomes, uncertainty or durable resume; consult its canonical schema only when creating/interpreting it. Never adopt a planned artifact or require a task recipe for autonomous work.

Identify concrete applicable test obligations: primary accepted behavior, introduced failure/boundary, material state/data invariant, owned seam contract and fixed-defect regression. Tests prove observable repository-owned results, state changes, errors or meaningful outbound contracts. Mocks at external seams are valid when assertions establish owned behavior. Mock setup, framework internals, private structure and insignificant call counts do not satisfy obligations. Consult doctrine for uncertain classification, materially revised obligations or exemptions. Never invent inapplicable tests or weaken existing assertions merely to reach green.

Implement within accepted intent. Run the smallest relevant unit-test target and cheap build/type/lint gate. Broad affected-project, integration and e2e checks belong at final verification. Complete an outcome only when meaningful tests are green or an allowed exemption names its reason and closest observable check. Inspect the outcome diff and maintain relevant documentation. Record material decisions and unresolved facts without expanding the feature.

Append a compact Outcome checkpoint: commit reference, result, named cases/commands/results or valid exemption, new durable facts. Update any execution map and create a local outcome checkpoint containing only owned paths. Use `this checkpoint` when evidence is committed with its own entry; Git resolves the introducing revision. Do not repeat global final-evidence fields at each outcome. Existing full intermediate entries remain append-only history.

Clean checkpoints must permit recovery from repository state without conversation. Discard raw logs/dialogue; rotate context when reasoning quality is at risk. Save captures unresolved context, not dirty source durability. Evidence that changes accepted behavior/scope, public contracts, security/data, migration or material cost requires an accepted amendment and relevant canonical interpretation before implementation continues.

## Final verification

Deliberately reload all accepted outcomes/constraints and amendments, outcome coverage and complete `base_commit..HEAD`. Recheck coverage and inspect the full diff for scope, cross-outcome inconsistency and garbage. Run the authoritative affected-project/changeset suite once per attempt and exercise the primary accepted path, without separately rerunning integration/e2e commands already included.

If the primary path cannot be exercised within scope, record why and the closest whole-feature check actually performed under the doctrine. Compilation/packaging alone is not primary-path exercise unless producing that artifact is the accepted behavior. Correct failures and verify before delivery, checkpointing coherent corrections.

Read the complete final Build Evidence schema from artifact contracts. Append every current field, named tests/results or exemptions, whole-feature path, decisions/deviations and execution state. Validate freshness against source/tests being delivered; set In Review and checkpoint the handoff. Any later source/test change invalidates final evidence: repeat affected final verification and append a new complete entry. Lifecycle-only and Review-artifact commits do not invalidate it.

Read the [harness contract](../references/harness-command-contract.md) for the active-host Review handoff. End with resolved Brief and Review paths and a copy-ready continuation. Emitting it does not invoke Review or authorize Ship.
